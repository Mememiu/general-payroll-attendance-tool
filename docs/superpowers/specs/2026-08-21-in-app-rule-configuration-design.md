# App 内规则配置中心设计

## 1. 目标与边界

通用离线薪酬工具不再要求 HR 在月度计算流程中上传规则包工作簿。HR 通过 App 内的配置页面维护公司制度、法定政策、商业保险、员工例外和月度任务。所有影响计算的参数必须来自 HR 已保存并发布的规则版本，产品不得静默带入任何公司的上下班时间、每日标准工时、月平均计薪天数、假勤比例、地区费率或保险基数。

规则版本仍然保留，但它是 App 内部用于计算、审计和历史追溯的数据快照，不是 HR 每月必须准备和上传的文件。规则导入和导出仅用于本地备份、换机迁移和故障恢复，放在高级设置中，不进入日常计算流程。

首期继续通过固定格式 XLSX 导入考勤和员工薪酬主数据。员工薪酬主数据与公司规则分离，工号是唯一匹配键，姓名只用于展示。

## 2. 信息架构

左侧主导航保持精简：

1. 薪酬计算：创建或选择月度任务，上传考勤和员工薪酬主数据，预检、复核、计算和导出。
2. 规则配置：维护所有计算制度和规则版本。
3. 使用说明：模板说明、字段说明、异常处理和数据安全说明。
4. 高级设置：规则备份导入/导出、数据目录和诊断信息。该入口弱化展示，不参与月度流程。

规则配置页使用顶部标签：

- 公司制度
- 法定政策
- 商业保险
- 员工例外
- 月度任务

页面顶部固定显示当前规则的名称、版本、状态、生效日和最后更新时间。草稿状态提供“保存草稿”“检查配置”“发布版本”；已发布版本只读，修改时必须“复制为新版本”。

## 3. 公司制度

公司制度按业务区块组织，不使用一张无限增长的大表单：

- 工时与班次：工时模式、标准上下班、午休、每日标准工时、迟到/早退、弹性范围、核心时段、补足规则和单卡处理。
- 入离职：起薪/止薪、入职日和离职日是否按满勤、当日有审批时的计算方式。
- 假勤类型：表格展示名称、分类、计薪比例、是否计入出勤、是否影响全勤、是否进入病假扣款、状态和操作。
- 加班与调休：加班起算方式、审批要求、跨午夜、是否计现金、费率/公式方案、是否转调休和转换比例。
- 薪资制度：月平均计薪天数、每日标准工时引用、月薪/日薪/时薪方案、试用期、实习和实习转正规则、扣款系数、全勤奖及舍入方式。

假勤类型允许 HR 不限数量新增。新增或编辑使用弹窗，必须填写唯一编码、名称、分类、计薪方案、计薪参数、是否计入出勤、是否影响全勤、扣款归类和启用状态。任何必填字段缺失都不能发布规则。

系统可以提供病假、事假、调休假、带薪年假、无薪年假、丧假、婚假、产假、陪产假、哺乳假、外出、出差和加班等名称候选，但不得预填计薪比例或考勤结果。HR 删除已被历史版本引用的类型时，实际执行停用，不破坏历史数据。

## 4. 法定政策

法定政策分为个人所得税、社会保险和住房公积金：

- 个税：计税制度、基本减除费用、累计预扣税率表、专项附加扣除入口、负税额处理和生效日。
- 社会保险：养老、医疗、失业、工伤、生育按险种独立启停和配置。
- 公积金：基数模式、上下限、个人/单位费率、缴纳时间规则和生效日。

每个险种必须填写地区、政策来源、生效日期、基数模式、基数上下限、个人费率、单位费率和适用用工类型。费率输入统一显示百分比，存储为高精度小数。App 不联网查询地区政策，也不预设地区、基数和费率。

入职和离职当月是否缴纳、五险与公积金是否使用不同截止日，均由 HR 在页面明确选择，不使用隐藏的 15 日默认规则。

## 5. 商业保险

商业保险使用表格管理，支持新增、编辑、停用和删除未引用草稿项。每个险种配置：

- 险种名称、地区和生效日期
- 固定金额或基数乘费率
- 个人与单位承担比例
- 是否计税、是否计入应发、代扣方式
- 适用用工类型

商业保险不得复用五险一金的隐式默认值。历史版本引用的险种只能停用，不能物理删除。

## 6. 员工例外

员工默认继承已发布公司规则，只维护差异项。列表以工号为主键，展示姓名、部门、用工类型、薪资摘要、社保状态、公积金档位和例外数量。

新增或编辑员工例外使用弹窗，支持特殊社保/公积金基数、特殊档位、是否缴纳、全勤奖覆盖、奖金补贴、试用期、实习转正日期及薪资等。每次覆盖必须填写原因和生效区间。员工填写全勤奖覆盖金额为 0 表示明确取消该员工当期全勤奖；留空表示继承公司规则。

员工主数据仍可通过固定 XLSX 批量导入。页面编辑与文件导入必须走同一套字段校验和工号唯一性校验。

## 7. 月度任务与计算页

月度任务保存任务名称、计薪月份、起薪日、止薪日、已发布规则版本和状态。规则配置页可以管理任务模板，但实际文件上传集中在薪酬计算页。

薪酬计算页只要求：

1. 选择或新建月度任务。
2. 上传当前周期考勤 XLSX。
3. 上传员工薪酬主数据 XLSX。
4. 执行预检、处理异常、计算并导出。

月度计算页不再出现“上传规则包”。任务只能引用已发布且覆盖计薪周期的规则版本。草稿规则可以运行配置预检和模拟计算，但不得生成正式工资结果。

## 8. 保存、校验与发布

配置采用三级动作：

- 保存草稿：允许暂时缺少字段，保存当前填写内容并显示未完成项。
- 检查配置：执行字段、枚举、范围、日期和跨模块校验，返回可直接定位到控件的错误。
- 发布版本：仅在全部校验通过后生成不可修改的规则快照。

页面按需显示字段。例如关闭某险种后不要求填写费率；选择固定金额商业保险后不显示基数和费率；选择固定工时时不显示弹性核心时段。隐藏字段不能残留旧值参与计算，保存时必须按当前方案清理或忽略。

跨字段校验至少包括：上下班与午休是否形成合法区间、每日标准工时是否与制度配置一致、费率和比例范围、基数上下限、规则生效日期、假勤编码重复、公式方案所需参数、员工工号唯一性以及月度任务是否引用有效规则版本。

## 9. 本地存储与历史保护

建议使用本地 SQLite 保存草稿、版本元数据、月度任务和员工例外；已发布规则同时保存规范化 JSON 快照。计算任务记录规则版本编号、快照摘要、输入文件指纹、计算时间和人工覆盖。

已发布规则不可直接编辑。政策变化时复制旧版本，设置新版本号和生效日后再发布。历史工资始终引用原快照，不因当前规则变化而重算或改变。

首次升级时，现有 XLSX 规则包可由迁移程序解析为 App 内草稿，HR 检查并发布后使用。迁移不得自动发布，也不得将测试示例值当作真实制度。

## 10. 高级备份

高级设置提供：

- 导出完整规则备份，包含版本、快照、员工例外和必要元数据。
- 导入备份并预检冲突，不直接覆盖现有版本。
- 显示备份生成时间、产品数据格式版本和摘要。

备份文件不是月度计算输入。导入同编号同版本但内容摘要不同的规则时必须阻断，并要求复制为新版本或取消导入。

## 11. 错误处理与测试

所有保存和发布错误必须在页面顶部汇总，并在对应控件旁显示原因。网络请求失败、磁盘不可写、数据库损坏、版本冲突和模板解析失败都不得表现为按钮无响应。

实施至少覆盖：

- 草稿保存、恢复和跨页面切换
- 条件字段显示及隐藏值不参与计算
- 假勤和险种的新增、编辑、停用及历史引用保护
- 空配置不能发布，完整配置可发布
- 已发布版本不可修改，复制后可编辑
- 月度任务只能使用有效已发布版本
- 规则变化不改变历史任务
- 备份导入/导出及版本冲突
- 不同屏幕尺寸下表单、表格和弹窗无重叠
- 原公司规则值不会作为通用版默认值出现

## 12. 实施顺序

1. 建立本地配置数据模型、存储和校验接口。
2. 实现规则版本的草稿、检查、发布和复制。
3. 重做规则配置页面及各业务表单。
4. 调整月度计算页，移除规则工作簿上传并改为规则版本引用。
5. 将页面配置转换为现有考勤和薪资计算模型。
6. 实现高级备份和旧规则包迁移。
7. 完成端到端回归、桌面与移动窗口检查和文档更新。
