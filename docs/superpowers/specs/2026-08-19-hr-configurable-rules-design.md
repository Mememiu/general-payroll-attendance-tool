# HR 可配置考勤与薪酬规则设计

## 目标

通用离线版不得继承任何单一公司的上下班时间、迟到边界、每日工时、计薪天数、加班规则、假勤比例或五险一金政策。所有影响考勤和薪酬的制度由 HR 在版本化规则包中明确配置，员工层只维护例外。

系统可以提供字段、下拉选项和受控公式模板，但不能预填可直接生效的公司规则。必填规则缺失或互相矛盾时阻断整批计算，不允许用代码兜底值继续出薪。

## 配置分层

1. 公司制度：考勤、假勤、计薪、全勤奖、加班和入离职处理。
2. 法定政策：个税、五险、公积金及其地区、生效期、基数和费率。
3. 商业保险：独立于法定五险一金，支持公司承担、员工分摊和计税属性。
4. 员工例外：用工类型、薪资、试用期、转正、缴纳状态、档位、特殊基数和奖励覆盖。
5. 月度任务：计薪月份、起止日期、当期考勤文件和适用规则包版本。

## HR 模板

模板只预填不可编辑的模板版本以及结构性代码，不预填业务数值。所有时间、小时、金额、比例、地区和政策参数由 HR 填写。

### 用工类型

- 社招全职
- 校招全职
- 外包
- 实习生
- 实习转正

用工类型用于选择默认计薪方案和法定缴纳资格。员工行允许 HR 覆盖，但覆盖必须留下审计记录。实习生默认不缴纳法定五险一金；实习转正按转正日期及 HR 的月度切换规则判断缴纳资格。

### 假勤类型

模板提供病假、事假、调休假、带薪年假、无薪年假、丧假、婚假、产假、陪产假、哺乳假、外出、出差和加班等常见结构行，并允许 HR 不设数量上限地新增其他假期类型。每一行必须配置：

- 计薪比例
- 是否计入正常出勤
- 是否计入缺勤
- 是否影响全勤
- 是否免打卡
- 是否需要证明
- 缺少证明时的处理方式
- 是否可跨日
- 计薪方案：按计薪比例 / 固定扣款 / 受控公式模板
- 扣款输出分类：病假扣款 / 考勤扣款 / 独立分类

HR 新增的假期不得继承任何预置假期的计薪规则。新增行必须填写唯一 `rule_code`、显示名称、计薪方案、计薪参数及全部考勤属性；任一必填项缺失、编码或名称重复、比例超出范围、公式参数不完整时，阻断规则包保存和月度计算。

假勤名称通过稳定的 `rule_code` 与计算分类关联，不能依赖中文名称完全匹配。病假等需要独立输出的类别通过类别代码进入对应明细列；HR 选择“独立分类”时，导出结果自动增加该假期的时长和扣款明细列。

## 考勤制度

### 共同参数

HR 必须填写每日标准工时、标准上下班、一个或多个休息时段、最早有效打卡、工作制和打卡异常处理。正常工时以 HR 填写的 `daily_required_hours` 为唯一封顶和满勤基准，不枚举或预设任何小时数。输入值在导入时统一换算为整数分钟参与计算；不能精确换算到整分钟的值应在导入时提示 HR 修正。

实际覆盖时长按分钟计算：

```text
实际覆盖 = 打卡在岗时段 + 计入出勤的审批时段 + 已确认返岗时段
正常有效工时 = 实际覆盖合并去重 - 与休息时段的重叠
有效工时 = min(正常有效工时, HR每日标准工时)
```

加班时段不混入正常有效工时。审批与打卡重叠时只计算一次。所有统计先按分钟计算，最后显示时再换算小时。

### 固定工时

固定工时以 HR 填写的固定班次为考勤边界。HR 选择是否允许早到早走以及是否允许迟到后延时补足：

- 固定标准下班：正常覆盖最多计算到标准下班。
- 按到岗推算下班：下班边界按 HR 选择的推算策略计算。
- 迟到补足关闭：晚下班不抵扣迟到或早退。
- 迟到补足开启：只在 HR 配置的适用区间内补足。

宽限下班时间未填写时，宽限分钟为 0；不得自动增加 15 分钟。迟到时长从 HR 配置的迟到计时起点计算，并扣除覆盖该时段的有效审批。迟到超过 HR 配置的旷工阈值时，按 HR 选择的半日或整日旷工策略处理。

### 弹性工时

HR 必须选择一种模式：

1. 纯工时弹性：只比较每日有效工时，不统计迟到。
2. 最晚到岗限制：允许弹性到岗，但超过最晚到岗时间后统计迟到。
3. 核心时段覆盖：除满足每日工时外，还必须覆盖 HR 配置的核心时段；缺口计入异常。

弹性时长、最晚到岗、核心时段和迟到计时方式均由 HR 配置。选择不适用的字段必须留空，选择适用模式后相关字段必须填写。

### 打卡识别

考勤文本解析保留所有打卡，不再只把中间打卡完全忽略。系统先识别首卡、末卡、返岗卡和可能的离岗卡，再结合审批时间线计算。无法可靠配对的单卡、无卡、奇数卡和跨日记录进入人工复核，除非适用的审批规则明确免打卡。

粗粒度上午、下午、全天审批按 HR 班次映射：上午为上班至首个主要休息开始，下午为主要休息结束至下班，全天为完整工作班次。多休息时段和跨日班次必须由规则模型明确支持。

### 外出与出差返岗

外出或出差审批默认覆盖审批时段。只有审批段内出现可识别的返岗卡，并且后续存在审批结束后的有效下班卡时，才认为员工已经返岗并连续在岗：

```text
审批开始 -> 返岗卡：外出或出差
返岗卡 -> 下班卡：公司在岗
```

若两张卡都位于审批时段内，或审批结束后没有有效下班卡，不截断审批段并标记复核。该处理必须接入每日计算流水线，而不是仅保留未调用的辅助函数。

## 加班

HR 必须配置：

- 是否必须有审批
- 加班起算方式：审批开始 / 正常下班后 / 两者取较晚
- 最小加班时长和取整方式
- 是否允许跨午夜
- 是否发放加班费
- 是否转换调休
- 调休转换比例
- 加班费公式模板和费率参数
- 法定工作日、休息日、法定节假日是否使用不同费率

可选加班费公式为受控模板，例如：

```text
加班费 = 认可加班小时 x HR配置的小时费率
加班费 = 月薪 / 月计薪天数 / 每日标准工时 x 认可加班小时 x 倍率
```

未开启加班费时金额为 0。开启后缺少费率、倍率或工资基数时阻断计算。调休余额与加班费分别输出；HR 可以选择只发加班费、只转调休、两者并行或均不处理。

## 入职、离职和试用期

入职日、离职日是否按满勤由 HR 分别选择。启用且当天没有假勤审批时，按每日标准工时计满；关闭时按实际打卡和审批计算。当天存在假勤审批时始终按审批计薪比例处理。

员工主数据增加试用期开始、试用期结束和试用期计薪方案。HR 必须从受控方案中选择；可选的月薪倍率方案为：

```text
试用期月薪 = 转正月薪 x 试用期薪资倍率
```

也可选择 HR 配置的固定试用期月薪或按日方案。日期重叠、结束早于开始或缺少必要薪资参数时阻断计算。

## 薪资公式

HR 先为用工类型选择受控计薪方案，再填写参数。首期支持：

1. 月薪按工时折算：月薪 / 月计薪天数 / 每日标准工时 x 有效工时。
2. 月薪按天折算：月薪 / 月计薪天数 x 有效计薪天数。
3. 固定月薪减扣款：月薪 - 考勤扣款 - 请假扣款。
4. 实习日薪时薪混合：满勤日 x 日薪 + 非满勤有效小时 x 时薪。
5. 实习转正拆分：转正日前使用实习方案，转正日起使用全职方案。

`monthly_pay_days` 和 `daily_required_hours` 必须传入薪资引擎，不得保留 21.75 天或 8 小时硬编码。考勤扣款系数和病假扣款系数由 HR 明确选择是否启用；启用时参与计算，关闭时不允许该字段悄悄改变结果。

公式执行采用受控枚举和参数，不执行 Excel 公式、Python 表达式或任意代码。金额按 HR 配置的小数位和舍入方式处理，默认模板不预选舍入规则。

## 全勤奖

HR 配置全勤资格条件，包括最低有效考勤天数、缺勤、迟到、早退、旷工、假勤类别和审批是否影响全勤。假勤表的“影响全勤”必须实际参与判断。

员工全勤奖处理分为：

- 继承公司金额
- 指定员工金额
- 取消
- 在公司金额上额外补发

金额为 0 不再承担多重语义；处理方式与金额分列，导出结果记录采用的来源。

## 五险、公积金和商业保险

五险与公积金分别配置启用状态、地区、生效期、基数模式、上下限、费率、档位和政策来源，不预设任何地区数值。

五险和公积金分别配置入离职缴纳规则，包括截止日、截止日是否包含、入职当月/次月起缴、离职当月是否缴纳。规则按计薪月份和员工日期判断，并允许员工级人工覆盖且留下原因。

实习生默认不缴纳；实习转正在转换后按 HR 的缴纳起算规则处理。社招全职、校招全职和外包的默认资格由 HR 在“用工类型政策”中配置。

商业保险使用独立工作表，支持险种、地区、生效期、适用人群、固定金额或基数费率、个人和单位承担比例、是否计税以及是否计入应发或代扣。商业保险不进入法定五险一金合计列。

## 个税

中国大陆模式使用版本化的法定累计预扣规则，包括基本减除费用、税率表和速算扣除数。HR 选择政策版本并填写员工累计历史数据，不允许任意修改法定税率后仍标记为中国大陆法定模式。

员工月度输入增加当月专项附加扣除和其他依法扣除金额。缺少非首月累计数据时阻断计算，不得默认历史收入、历史扣除和历史已缴税均为 0。只有明确标记为本年度首次计薪时，才允许以 0 初始化历史累计值。

中国大陆累计预扣的当月税额下限为 0；多缴税额进入后续月份或年度汇算，不作为负数工资项发放。其他地区或自定义税制在后续以独立税制插件扩展。

## 校验与审计

规则包保存和月度计算前执行交叉校验：

- 标准班次扣除休息后的可用时长与每日标准工时是否一致或有明确差异策略。
- 固定、弹性和核心时段字段是否完整且互斥。
- 假勤类别代码、计薪比例和输出分类是否完整。
- 加班费、调休和取整参数是否完整。
- 试用期、转正、入离职日期是否有效。
- 五险、公积金和商业保险规则在计薪月份是否生效。
- 非首月个税累计数据是否完整。
- 考勤文件工号是否能与员工主数据唯一匹配。

计算结果保存规则包编号、版本、生效日、输入文件指纹、公式方案、关键参数和人工覆盖记录。发生单卡、无法配对、未知审批、政策缺失或公式参数缺失时，不生成正式工资结果，只输出待修复清单。

## 迁移原则

现有模板升级后版本变更，旧规则包不得静默套用新语义。系统提示 HR 下载新模板并迁移。旧公司的 09:00、10:00、19:30、19:45、8 小时和 21.75 天只能存在于测试夹具或用户自行创建的规则包中，不能作为产品默认值。
