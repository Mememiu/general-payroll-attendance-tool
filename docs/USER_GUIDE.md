# 通用薪酬绩效工具使用指南

桌面安装和系统安全提示见[安装说明](INSTALL.md)，版本覆盖、自动迁移和故障恢复见[升级说明](UPGRADING.md)。

## 1. 使用流程

1. 在“规则配置”创建制度草稿。
2. 在公司制度、法定政策、商业保险、员工例外四个页签中完成配置。规则页只有这四个页签，用工类型位于“公司制度”页签。
3. 保存草稿并执行“检查规则”。校验通过后发布规则版本；已发布版本不可修改，需要变更时复制为新草稿。
4. 在“薪酬计算”选择计薪月份、起薪日、止薪日和已发布规则版本。
5. 只上传当前周期考勤 XLSX 与员工薪酬 XLSX。规则在 App 内配置和发布，计算时不上传规则包。
6. 提交计算后到“计算记录”核对状态、异常/例外数量和结果可用性，再下载结果。

所有数据只保存在运行 App 的当前电脑。工号是考勤与员工薪酬数据的匹配键，姓名只用于展示。

## 2. 规则配置

规则名称、版本号和生效日用于创建草稿。规则编辑区带 `*` 的项目必填；选择某种模式或“启用”后出现的条件字段也必须填写。每日标准工时和月平均计薪天数都由 HR 输入，App 不提供业务默认值。

### 公司制度

#### 工时、薪资与收入项目

- 工时模式、每日标准分钟、名义上班时间、名义下班时间和是否启用午休始终必填。固定工时下，每日标准分钟不能超过名义上下班区间扣除午休后的可用分钟。
- 选择弹性工时后必须选择弹性策略；选择“限制最晚到岗”时填写最晚到岗时间，选择“要求核心时段”时填写核心开始和核心结束时间。即使选择“只核算工时”，名义上下班时间仍用于审批日边界。
- 启用午休后必须填写午休开始和结束时间，且午休必须位于名义上下班区间内。
- 月平均计薪天数必须大于 0；全勤奖不得小于 0；金额小数位和舍入方式必须明确填写。
- 补贴与奖金都必须分别明确：是否计税、是否计入社保基数、是否计入公积金基数。这里只配置口径，员工当月金额填写在员工薪酬文件。

#### 用工类型

至少配置一种启用的用工类型。代码只能使用小写字母、数字和下划线，并以小写字母开头，例如 `full_time`、`intern`、`outsourced`。每种类型必须填写唯一代码、唯一名称、薪资方案，并分别选择是否适用社保、公积金和个税，以及是否启用。

代码会写入员工薪酬文件，并被法定政策、商业保险和员工例外引用。已经保存或被引用的代码不要改名；制度变化时新建代码并停用旧代码。实习、外包等名称不会自动决定缴纳资格，三项适用性必须由 HR 明确选择。

#### 假勤与加班

- 假勤项目的代码、名称和启用状态始终必填。启用后还必须填写分类、计薪方式、扣款归类，并明确是否计入出勤、是否计入缺勤、是否影响全勤、是否免打卡、是否需要证明、是否允许跨日。
- 当前界面支持按比例计薪；选择后必须填写 0 到 1 的计薪比例。固定扣款、受控公式以及“缺少证明时如何处理”的独立输入控件尚未接入，不要在当前版本选择这些未完成口径。当前计算也不会读取请假证明状态，相关证明必须由 HR 在发薪前人工核查。
- 加班的启用状态、是否计算现金加班费、是否转换调休始终必填。启用加班后，起算方式、最小分钟、分钟取整、是否必须审批、是否允许跨午夜均必填。
- 计算引擎按 HR 选择的“从审批开始”“从正常下班后开始”或“取两者较晚值”确定加班起点。跨午夜是否允许以已发布规则为准；同一天连续或重叠的加班审批先合并，再检查当日总分钟是否达到最低门槛，达到后按“实际分钟”“向下取整到 30 分钟”或“向上取整到 30 分钟”确认认可加班。
- “必须审批=是”时，只有包含明确起止时间的加班审批可自动认可；上午、下午、全天等粗粒度加班或只有晚下班卡的记录进入人工复核。“必须审批=否”且没有加班审批时，系统使用完整上下班卡，从 HR 规则推算的正常下班边界到实际下班卡统计原始加班；单卡或无卡不会推测。
- 加班与请假、外出或其他非加班审批发生时间重叠时，系统保留原始加班时长并进入人工复核，本期认可加班、现金加班费和调休新增分钟均暂按 `0`，不得静默重复结算。
- 启用现金加班费后，还必须选择“员工时薪乘倍率”或“固定小时费率”，填写现金费率，以及工作日、休息日、法定节假日三类倍率。现金加班费进入应发、应税收入、实发和单位总成本，但不进入社保或公积金缴费基数。
- 启用转调休后必须填写转换比例。结果只输出本期新增调休分钟，例如认可加班 120 分钟、转换比例 1.5，输出新增调休 180 分钟；App 不维护历史余额、已使用分钟或跨月结余，HR 仍需在调休台账中入账。

### 法定政策

法定险与住房公积金是依据适用政策配置的法定缴纳项目；商业保险是公司自愿购买的福利项目，两者不能用同一开关、费率或成本列相互替代。App 离线运行，不联网查询地区政策，也不内置城市费率。

- 个税启用状态始终必填。启用后，计税制度、每月基本减除费用、生效日、负税额处理方式和至少一档累计预扣税率均必填；每档必须填写起点、税率和速算扣除数，首档起点为 0，后续起点递增。
- 每个五险或公积金项目的代码、名称和启用状态始终必填。启用后，档位代码、地区、生效日、政策来源、适用用工类型、基数模式、基数上下限、个人费率和单位费率均必填；基数模式选择固定基数时，固定基数必填。失效日可留空，但填写时不得早于生效日。
- 每条五险和住房公积金规则都要分别选择入职当月、离职当月的缴纳方式：始终缴纳、始终不缴纳或按截止日判断。App 不预设 15 日；选择按截止日判断时，HR 必须填写 1 至 31 日。
- 入职按截止日判断时，入职日小于或等于截止日则当月缴纳，晚于截止日则当月不缴纳。离职按截止日判断时，离职日小于或等于截止日则当月不缴纳，晚于截止日则当月缴纳。同一员工在同一个月入职又离职时，入职规则和离职规则必须同时允许，才会产生当月缴费。
- 员工是否实际适用还会同时受到用工类型、员工文件缴纳开关和员工例外约束。

### 商业保险

商业险项目的代码、名称和启用状态始终必填。启用后必须填写地区、生效日、计费方式、个人与单位承担比例、扣款方式、适用用工类型、是否计税和是否计入应发；承担比例合计必须为 1。固定金额方式必须填写金额，基数费率方式必须填写个人和单位费率。失效日可留空，但不得早于生效日。

固定金额按承担比例拆分；基数费率按配置费率计算。工资代扣进入个人商业险扣款，公司承担进入单位商业险成本；报销计入应发时不会在单位总成本中重复计入同一金额。

### 员工例外

员工例外只用于单个员工长期存在或有明确生效区间的差异。支持法定险/公积金的启用状态、档位和基数，商业险启用状态、金额和基数，用工类型，以及全勤奖金额覆盖。奖金、补贴和当月专项附加扣除不是员工例外，必须按员工、按月填写在员工薪酬文件。

- 工号、覆盖类型、目标项目、覆盖值、生效日、原因和启用状态必填；失效日可留空，但不得早于生效日。
- 启用状态覆盖必须选择“是”或“否”；档位和用工类型填写已存在的启用代码；固定基数、商业险金额/基数和全勤奖金额必须为非负数；基数模式只能选择固定基数、薪资全额或继承公司规则。
- 同一员工、同一覆盖类型和同一目标项目的启用区间不得重叠。月度计算只采用在起薪日已经生效的普通例外，不会把月中才生效的配置扩大为整月。
- 用工类型例外必须覆盖完整计薪周期。月中实习转正应使用“实习转正分段”薪资方案，并在员工薪酬文件填写转正日期。

## 3. 员工薪酬文件

工作表名为 `员工薪酬`。必须保留 `employee_id` 和 `employment_type` 两列；其他标准字段按需要填写，字段代码及含义见[员工薪酬文件说明](hr-workbook.md)。

| 类别 | 字段 |
| --- | --- |
| 身份 | `employee_id`、`employee_name`、`employment_type` |
| 任职日期 | `hire_date`、`termination_date`、`conversion_date` |
| 薪资 | `monthly_salary`、`intern_daily_rate`、`intern_hourly_rate` |
| 当月收入 | `allowance`、`bonus`、`perfect_attendance_override` |
| 法定缴纳 | `statutory_enabled`、险种档位、社保/公积金基数覆盖 |
| 累计个税 | `tax_year`、`prior_taxable_income`、`prior_special_deductions`、`current_special_deductions`、`prior_withheld_tax` |

`employment_type` 必须填写当前已发布规则中的启用代码。月薪方案填写 `monthly_salary`；实习日薪/时薪方案填写 `intern_daily_rate` 和 `intern_hourly_rate`；实习转正分段方案同时填写转正日期、月薪、实习日薪和实习时薪。累计个税字段应来自本纳税年度已确认数据；非 1 月不能用全零替代真实累计数据。奖金和补贴参与计税、社保基数或公积金基数的方式，以已发布收入项目规则为准。

## 4. 迁移、备份与恢复

### 旧规则迁移

在“高级设置”上传旧 HR 规则工作簿，只会生成草稿，不会直接发布。旧工作簿不会自动生成结构化用工类型；迁移后必须在“公司制度”中逐项新建用工类型，补全代码、名称、薪资方案、社保适用性、公积金适用性和个税适用性，再检查其余三个规则页签。字段未补齐时校验不会通过，也不能发布。

### 发布与升级

- 已发布版本是不可变快照；需要调整时复制已发布或已停用版本，填写新版本号和生效日，在新草稿中修改后再发布。停用旧版本不会改写历史快照。
- 升级 App 前，先在“高级设置”导出规则备份 ZIP，并把已下载的历史结果另行备份。规则备份包含规则版本及其状态和摘要，不包含考勤文件、员工薪酬文件、计算记录或结果 XLSX。
- 桌面安装包的数据位于系统用户数据目录；完整路径和恢复方式见升级说明。源码开发模式才使用仓库 `instance` 目录。不要直接编辑数据库或任务文件。

### 草稿失败恢复

草稿保存或校验失败不会修改任何已发布版本，也不会改变历史计算记录或结果。校验失败时按页面字段错误修复草稿、重新保存并再次检查；页面中断时重新打开最后一次成功保存的草稿。若草稿内容已不可信，从正确的已发布版本复制新草稿后继续，不要修改数据库、已发布快照或历史结果文件来绕过校验。

## 5. 计算记录与结果核对

计算记录用于证明某次月度计算使用了哪个不可变规则快照和哪组输入摘要：

- `任务编号` 标识一次计算；`规则摘要` 是已发布快照的哈希标识，不是可编辑规则值。
- `员工数` 是本次结果中的员工数量；`异常/例外数` 是本次启用的员工例外与考勤人工复核项数量之和，不能直接当作错误员工数。
- `计算中` 表示任务尚未完成；`已完成` 表示结果生成且没有考勤复核项；`待复核` 表示结果已生成，但存在单卡、缺卡或无法自动确认的审批记录；`失败` 表示未生成可用结果，行上会保留经过脱敏的失败摘要。
- `结果可用` 表示结果文件已成功写入。制度后续修改或新版本发布不会重算、覆盖或改写已有记录。

结果分别列示考勤扣款、病假扣款、五险一金个人扣款、商业险个人代扣、个税、实发工资、单位五险一金成本、单位商业险成本和单位总成本。个税结转模式还会输出超扣结转余额。加班部分分别输出原始加班小时、认可加班小时、本期新增调休分钟和现金加班费；现金结算关闭时加班费为 `0`，调休分钟只代表本期新增量，不代表可用余额。

首次核对至少抽查：新入职、离职、同月入离职、实习转正、跨午夜加班、单卡/缺卡、带薪与无薪假、多个社保档位、商业险员工覆盖及非 1 月累计个税员工。
